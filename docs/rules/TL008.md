# TL008: Background service without tenant scope

## What it detects

`BackgroundService` or `IHostedService` implementations that inject a DbContext with tenant-scoped entities but do not appear to create a service scope or set the tenant context.

## Why it matters

Background services run outside the HTTP request pipeline. There is no ambient tenant context, no `HttpContext`, and no scoped DI container. A DbContext injected directly will either use the default (empty) tenant or the tenant from a previous request, causing cross-tenant data leaks or missing data.

## Examples

### Bad

```csharp
public class OrderProcessor : BackgroundService
{
    private readonly AppDbContext _db;
    public OrderProcessor(AppDbContext db) => _db = db;

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        var orders = await _db.Orders.ToListAsync(ct); // No tenant set!
    }
}
```

### Good

```csharp
public class OrderProcessor : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    public OrderProcessor(IServiceScopeFactory sf) => _scopeFactory = sf;

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        using var scope = _scopeFactory.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var orders = await db.Orders.ToListAsync(ct);
    }
}
```

## How to suppress

Mark the class with `[CrossTenant("reason")]`.

## False-positive notes

This is a heuristic check (Info severity). It may not detect all patterns of scope creation or tenant setting. If your background service uses `IServiceScopeFactory` or `IServiceProvider`, the diagnostic is suppressed.
