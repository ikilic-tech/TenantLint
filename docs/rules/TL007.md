# TL007: Tenant context stored in static member

## What it detects

Static fields or properties whose name or type relates to tenant context (contains "Tenant" or matches a configured tenant property name). The diagnostic message says "Static field" for fields and "Static property" for properties.

## Why it matters

Static fields are shared across all requests and all tenants in the same process. Storing tenant identity in a static field means one request's tenant value will be visible to all other concurrent and subsequent requests, causing cross-tenant data leaks.

## Examples

### Bad

```csharp
public class TenantContext
{
    public static string CurrentTenantId; // Shared across all requests!
}
```

### Good

```csharp
public class TenantContext
{
    private static readonly AsyncLocal<string> _tenantId = new();
    public static string CurrentTenantId
    {
        get => _tenantId.Value;
        set => _tenantId.Value = value;
    }
}
```

## How to suppress

If the static field is intentionally shared (e.g. a default value), change its name to not include "Tenant" or suppress via `.editorconfig`.

## False-positive notes

`AsyncLocal<T>`, `IHttpContextAccessor`, and Finbuckle's `IMultiTenantContextAccessor` are excluded because they are backed by `AsyncLocal` and are safe for per-request state.

Static `readonly` fields and get-only properties are only reported when the type is a tenant-context abstraction (type name ends with `TenantContext`, `CurrentTenant`, `TenantProvider`, `TenantAccessor`, `TenantInfo`). Static readonly fields whose type is a DTO, options, settings, or theme (e.g. `TenantThemeDto.Default`) are not reported — these are safe immutable defaults, not mutable per-request state.
