# TL006: Cache key does not include tenant identifier

## What it detects

`IMemoryCache`, `IDistributedCache`, or `HybridCache` calls where the cache key is a constant string or an interpolation that does not include a tenant-related value, and the containing method also accesses tenant-scoped data.

## Why it matters

When tenant-scoped data is cached with a key that does not include the tenant identifier, cached data from one tenant can be returned to another tenant.

## Examples

### Bad

```csharp
public List<Order> GetOrders(AppDbContext db)
{
    return _cache.GetOrCreate("orders", entry =>
    {
        return db.Orders.ToList();
    });
}
```

### Good

```csharp
public List<Order> GetOrders(AppDbContext db, string tenantId)
{
    return _cache.GetOrCreate($"orders:{tenantId}", entry =>
    {
        return db.Orders.ToList();
    });
}
```

## How to suppress

Mark the method with `[CrossTenant("reason")]` if the cache is intentionally shared across tenants.

## False-positive notes

Non-constant cache keys (e.g. `_cache.Set(GetKey(), ...)`) are not flagged because the key cannot be analyzed statically. Methods that do not touch tenant-scoped data are not flagged even if the cache key lacks a tenant identifier.
