# TL013: Raw ADO.NET SQL references tenant table without tenant filtering

| Property   | Value              |
|------------|--------------------|
| ID         | TL013              |
| Category   | TenantIsolation    |
| Severity   | Warning (see also TL113: Info when tenant column appears in predicate) |
| Enabled    | Yes                |
| Code Fix   | No                 |

## What it detects

TL013 fires when raw SQL written through ADO.NET APIs references a known tenant table name:

1. **`DbCommand.CommandText` assignment** — assigning a constant or interpolated SQL string to `CommandText` on any type that derives from `System.Data.Common.DbCommand` or implements `System.Data.IDbCommand`.
2. **DbCommand-derived constructor** — passing a constant or interpolated SQL string to a constructor of a type that derives from `DbCommand` (e.g., `new SqlCommand("...", conn)`).

## Why it leaks

ADO.NET commands bypass EF Core's global query filters entirely. When a raw SQL statement references a tenant-scoped table without filtering by the tenant column, it can read or modify data across all tenants.

```csharp
// This deletes rows from ALL tenants, not just the current one:
using var cmd = new SqlCommand("DELETE FROM Customers WHERE IsDeleted = 1", conn);
cmd.ExecuteNonQuery();
```

## Severity logic

- **TL013** (Warning, default): The SQL references a tenant table but no tenant column appears in a `WHERE`, `ON`, `AND`, or `OR` clause with a parameter placeholder.
- **TL113** (Info): A tenant column name (e.g., `tenant_id`, `TenantId`) appears in a predicate clause (`WHERE`, `ON`, `AND`, `OR`) adjacent to a parameter placeholder (`@param`, `{0}`, `$1`, `:param`). The filter is likely present but should be verified.

Tenant column in a `SELECT` list, `ORDER BY`, or `GROUP BY` does **not** downgrade to Info.

## Examples

### Bad (Warning)

```csharp
// TL013: 'CommandText' references tenant table 'Customers' in raw SQL
// without apparent tenant filtering.
cmd.CommandText = "DELETE FROM Customers WHERE IsDeleted = 1";
```

```csharp
// Also flagged — constructor pattern:
var cmd = new SqlCommand("DELETE FROM Customers", conn);
```

### Informational (Info)

```csharp
// Tenant column in WHERE with parameter — downgraded to TL113 Info:
cmd.CommandText = "DELETE FROM Customers WHERE TenantId = @tid AND IsDeleted = 1";
```

### Good (no diagnostic)

```csharp
// Non-tenant table — no diagnostic:
cmd.CommandText = "DELETE FROM Countries WHERE Id = 1";
```

```csharp
// Non-constant SQL — no diagnostic (cannot analyze):
cmd.CommandText = GetSql();
```

```csharp
// Marked as intentional cross-tenant access:
[CrossTenant("Admin cleanup applies to all tenants")]
public void CleanupDeletedRecords(DbConnection conn)
{
    using var cmd = conn.CreateCommand();
    cmd.CommandText = "DELETE FROM Customers WHERE IsDeleted = 1";
    cmd.ExecuteNonQuery();
}
```

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL013.severity = none
```

Or mark the method with `[CrossTenant("reason")]`:

```csharp
[CrossTenant("Billing reconciliation requires cross-tenant data")]
public void Reconcile() { ... }
```

## False-positive notes

- **Non-constant SQL** is not analyzed. If the SQL is built at runtime (e.g., `GetSql()`, string concatenation with non-constant values), TL013 does not report.
- **Non-tenant tables** are not flagged. Only tables associated with tenant-scoped entities (discovered via `HasQueryFilter` or convention) are checked.
- **Global entities** (configured via `tenantlint.global_entities`) are excluded.
- **User-defined classes** with a `CommandText` property that do not derive from `DbCommand` or implement `IDbCommand` are not flagged.
- **Word boundaries** are checked. A table named `Customers` will not match SQL containing `CustomerLogs`.
- **Heuristic limitation**: The predicate detection uses simple keyword scanning, not full SQL parsing. Complex subqueries or CTEs may not be correctly classified.
