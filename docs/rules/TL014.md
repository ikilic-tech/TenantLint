# TL014: ABP tenant-filter bypass

## What it detects

ABP Framework calls that bypass or switch tenant isolation:

- `IDataFilter.Disable<IMultiTenant>()` — disables the ABP tenant query filter
- `IDataFilter<IMultiTenant>.Disable()` — same, generic interface variant
- `ICurrentTenant.Change()` — switches the current tenant context

## Why it matters

`Disable<IMultiTenant>()` removes the automatic tenant filter, exposing all tenants' data. `ICurrentTenant.Change()` switches tenant context, which can cause cross-tenant operations if not carefully scoped.

## Examples

### Bad

```csharp
public async Task<List<Product>> GetAllProducts()
{
    using (_dataFilter.Disable<IMultiTenant>())
    {
        return await _repository.GetListAsync();
    }
}
```

### Good

```csharp
[CrossTenant("Global product catalog shared across tenants")]
public async Task<List<Product>> GetAllProducts()
{
    using (_dataFilter.Disable<IMultiTenant>())
    {
        return await _repository.GetListAsync();
    }
}
```

## How to suppress

Mark the method with `[CrossTenant("reason")]`.

## False-positive notes

`IDataFilter.Disable<ISoftDelete>()` and other non-tenant filters are not flagged. Only `IMultiTenant` is considered a tenant bypass.
