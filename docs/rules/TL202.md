# TL202: [SuppressMessage] targeting TL rule without justification

## What it detects

`[SuppressMessage("TenantIsolation", "TLxxx")]` attributes that do not include a non-placeholder `Justification` string.

## Why it matters

The `Justification` property exists specifically to document why a suppression is safe. Without it, suppressions silently hide potential cross-tenant data leaks.

## Examples

### Bad

```csharp
[SuppressMessage("TenantIsolation", "TL001")]
public List<Customer> GetAllCustomers() { ... }
```

### Good

```csharp
[SuppressMessage("TenantIsolation", "TL001",
    Justification = "Admin billing view requires all customers for invoice reconciliation")]
public List<Customer> GetAllCustomers() { ... }
```

## How to suppress

Prefer `[CrossTenant("reason")]` over `[SuppressMessage]` for tenant isolation rules.

## False-positive notes

Placeholder justifications like `""`, `"TODO"`, `"reason"`, `"n/a"` are treated as missing.
