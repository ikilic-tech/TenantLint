# TL901: CrossTenant attribute should state a reason

| Property   | Value              |
|------------|--------------------|
| ID         | TL901              |
| Category   | TenantIsolation    |
| Severity   | Info               |
| Enabled    | Yes                |

## What it detects

TL901 fires when a `[CrossTenant]` attribute is applied to a method or class without providing a reason string. The reason documents **why** cross-tenant access is intentional, which is critical for code review and audit trails.

## Why it exists

Cross-tenant access is the most dangerous operation in a multi-tenant application. Every such access should be explicitly justified. A missing reason makes it impossible to distinguish intentional cross-tenant access from accidental suppression of tenant checks.

## Examples

### Bad

```csharp
[CrossTenant]  // TL901: no reason provided
public List<Customer> GetAllCustomers()
{
    return _context.Customers.IgnoreQueryFilters().ToList();
}
```

### Good

```csharp
[CrossTenant("Admin dashboard aggregates data across all tenants")]
public List<Customer> GetAllCustomers()
{
    return _context.Customers.IgnoreQueryFilters().ToList();
}
```

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL901.severity = none
```
