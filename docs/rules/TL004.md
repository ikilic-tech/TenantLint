# TL004: Tenant identity received from client input

| Property   | Value              |
|------------|--------------------|
| ID         | TL004              |
| Category   | TenantIsolation    |
| Severity   | Warning            |
| Enabled    | Yes                |
| Code Fix   | No                 |

## What it detects

TL004 fires in two scenarios:

**1. Binding-attribute parameters** — a method parameter whose name matches a configured tenant property name (default: `TenantId`) is bound from a client-controlled input source: `[FromHeader]`, `[FromQuery]`, `[FromRoute]`, `[FromForm]`.

**2. Direct header/query reads** — code reads a tenant value directly from `Request.Headers` or `Request.Query` using an indexer or `TryGetValue`:
- `Request.Headers["X-Tenant-Id"]`
- `Request.Headers.TryGetValue("X-Tenant-Id", out var value)`
- `Request.Query["tenantId"]`

Header name matching strips the `X-` prefix and dashes before comparing (case-insensitive). For example, `X-Tenant-Id` → `TenantId`. Query key matching is case-insensitive against the configured tenant property names.

Custom tenant property names can be configured via `tenantlint.tenant_property_names`.

## Why it leaks

The tenant identity should come from a trusted source — a JWT claim, an authenticated session, or a middleware-resolved value. When the tenant comes directly from the request (header, query string, route, or form), a client can impersonate any tenant by changing the value.

```csharp
// Client sends: GET /api/customers?tenantId=other-tenant
public IActionResult GetCustomers([FromQuery] string tenantId)
{
    // tenantId is controlled by the caller!
    return Ok(db.Customers.Where(c => c.TenantId == tenantId));
}
```

## Examples

### Bad (Warning)

```csharp
// TL004: Parameter 'tenantId' receives the tenant identity from client input (FromHeader)
public IActionResult Get([FromHeader] string tenantId) { ... }
```

```csharp
// TL004: Parameter 'tenantId' receives the tenant identity from client input (FromQuery)
public IActionResult Get([FromQuery] string tenantId) { ... }
```

```csharp
// TL004: Parameter 'tenantId' receives the tenant identity from client input (FromRoute)
[HttpGet("{tenantId}/customers")]
public IActionResult Get([FromRoute] string tenantId) { ... }
```

```csharp
// TL004: 'X-Tenant-Id' receives the tenant identity from client input (Request.Headers)
var tenantId = Request.Headers["X-Tenant-Id"];
```

```csharp
// TL004: 'tenantId' receives the tenant identity from client input (Request.Query)
var tenantId = Request.Query["tenantId"];
```

### Good (no diagnostic)

```csharp
// Derive tenant from JWT claim:
public IActionResult Get()
{
    var tenantId = User.FindFirst("tenant_id")!.Value;
    return Ok(db.Customers.Where(c => c.TenantId == tenantId));
}
```

```csharp
// Parameter name doesn't match tenant property names:
public IActionResult Get([FromHeader] string authToken) { ... }
```

```csharp
// Marked as intentional:
[CrossTenant("Admin lookup by tenant")]
public IActionResult Get([FromHeader] string tenantId) { ... }
```

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL004.severity = none
```

Or mark the method with `[CrossTenant("reason")]`:

```csharp
[CrossTenant("Admin endpoint — tenant resolved from authenticated super-admin context")]
public IActionResult SwitchTenant([FromRoute] string tenantId) { ... }
```

## False-positive notes

- **`[FromBody]`** is not flagged by TL004. Body binding of entity types is covered by [TL010](TL010.md).
- **`[FromServices]`** is not flagged — service injection is not client input.
- **Parameters without any binding attribute** are not flagged.
- **Parameter name match** is case-insensitive (`tenantId`, `TenantId`, `TENANTID` all match).
- **Header name normalization**: `X-` prefix and dashes are stripped before matching (`X-Tenant-Id` → `TenantId`).
- **Non-constant keys** in header/query indexer access are not flagged (only string literals are analyzed).
- **Custom property names** configured via `tenantlint.tenant_property_names` are checked.
- **Data-flow tracking** (whether the value actually reaches a query) is deferred to v0.3. In v0.2, TL004 reports the binding source regardless of how the value is used.
