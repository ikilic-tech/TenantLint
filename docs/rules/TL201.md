# TL201: #pragma warning disable TL rule without justification

## What it detects

`#pragma warning disable TLxxx` directives that do not have a justification comment on the same line or the line above.

## Why it matters

Suppressing a tenant isolation rule without explanation makes it impossible to distinguish intentional decisions from accidental suppressions. When an AI agent or another developer encounters a suppressed rule, the justification comment explains why the suppression is safe.

## Examples

### Bad

```csharp
#pragma warning disable TL001
var all = db.Customers.IgnoreQueryFilters().ToList();
#pragma warning restore TL001
```

### Good

```csharp
// Admin billing view — all customers needed for invoice reconciliation
#pragma warning disable TL001
var all = db.Customers.IgnoreQueryFilters().ToList();
#pragma warning restore TL001
```

Or on the same line:

```csharp
#pragma warning disable TL001 // Admin billing view
var all = db.Customers.IgnoreQueryFilters().ToList();
#pragma warning restore TL001
```

## How to suppress

Use `[CrossTenant("reason")]` on the method instead of `#pragma warning disable`. If you must use `#pragma`, add a comment explaining why.

## False-positive notes

Placeholder comments like `// TODO`, `// reason`, `// n/a`, `// temp`, `// fixme` are treated as missing justification.
