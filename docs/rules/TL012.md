# TL012: HasQueryFilter references a value not rooted in the DbContext instance

| Property   | Value              |
|------------|--------------------|
| ID         | TL012              |
| Category   | TenantIsolation    |
| Severity   | Warning            |
| Enabled    | Yes                |
| Code Fix   | No                 |

## What it detects

TL012 fires when a `HasQueryFilter` lambda that references a tenant property compares it to a value that is **not** an instance member of the DbContext. This includes local variables, static fields, static properties, and static method calls.

## Why it leaks

EF Core caches the compiled model the first time a DbContext type is used. Query filter expressions are part of this cached model. If the filter's value side references a local variable, static field, or any value not reachable through `this` (the DbContext instance), **the first tenant's value is frozen into the cached model and reused for every subsequent DbContext instance**.

Only values accessed through `this` (instance fields, properties, or method calls on instance members) are parameterized by EF Core — meaning they are re-evaluated per query using the current DbContext instance's state.

```csharp
// This LEAKS: localTid is captured once during model building, then reused forever
protected override void OnModelCreating(ModelBuilder m)
{
    var localTid = _tenantId; // ← local variable
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == localTid);
}
```

## Examples

### Bad

```csharp
// TL012: local variable — value baked into cached model
protected override void OnModelCreating(ModelBuilder m)
{
    var tid = GetCurrentTenant();
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == tid);
}
```

```csharp
// TL012: static field — value read once, never re-evaluated
public static string CurrentTenantId;

protected override void OnModelCreating(ModelBuilder m)
{
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == CurrentTenantId);
}
```

```csharp
// TL012: static method — called once during model building
protected override void OnModelCreating(ModelBuilder m)
{
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == TenantHelper.GetCurrent());
}
```

### Good

```csharp
// Instance field — EF Core parameterizes access through `this`
private readonly string _tenantId;

protected override void OnModelCreating(ModelBuilder m)
{
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == _tenantId);
}
```

```csharp
// Property on an instance field — also parameterized through `this`
private readonly ITenantService _tenantService;

protected override void OnModelCreating(ModelBuilder m)
{
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == _tenantService.TenantId);
}
```

```csharp
// Method call on an instance field — re-evaluated per query
private readonly ITenantResolver _resolver;

protected override void OnModelCreating(ModelBuilder m)
{
    m.Entity<Order>().HasQueryFilter(e => e.TenantId == _resolver.GetTenantId());
}
```

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL012.severity = none
```

## False-positive notes

- **Non-tenant filters** (e.g., `e => !e.IsDeleted`) are not flagged. TL012 only analyzes the value side of comparisons involving a tenant property.
- **Constants and literals** (e.g., `e => e.TenantId != ""`) are not flagged — these are intentionally fixed values.
- **`IEntityTypeConfiguration`** classes are not analyzed by TL012 in v0.2. If you define tenant filters in a configuration class, ensure the value is accessed through the DbContext instance (typically passed via constructor injection from the DbContext).
