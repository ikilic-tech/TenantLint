# TL010: Tenant-scoped entity bound from request body

| Property   | Value              |
|------------|--------------------|
| ID         | TL010              |
| Category   | TenantIsolation    |
| Severity   | Warning            |
| Enabled    | Yes                |
| Code Fix   | No                 |

## What it detects

TL010 fires when a tenant-scoped entity type is used as a parameter bound from the request body in an ASP.NET Core action method. This includes:

1. **Explicit `[FromBody]`** — a parameter decorated with `[FromBody]` whose type is a tenant-scoped entity.
2. **Explicit `[FromForm]`** — a parameter decorated with `[FromForm]` whose type is a tenant-scoped entity.
3. **Implicit body binding** — on an `[ApiController]` class, a complex-type parameter with no explicit binding attribute is implicitly body-bound. If that type is a tenant-scoped entity, TL010 fires.

## Why it leaks

When a tenant-scoped entity is bound directly from the request body, the client controls every property — including the tenant identifier. A malicious or buggy client can set `TenantId` to any value, inserting or updating data under a different tenant.

```csharp
// Client sends: { "Name": "Evil Corp", "TenantId": "other-tenant" }
[HttpPost]
public IActionResult Create([FromBody] Customer customer)
{
    db.Customers.Add(customer); // Saves with the wrong TenantId!
    db.SaveChanges();
    return Ok();
}
```

## Examples

### Bad (Warning)

```csharp
// TL010: 'Customer' is a tenant-scoped entity bound from the request body
[HttpPost]
public IActionResult Create([FromBody] Customer customer) { ... }
```

```csharp
// Implicit binding on [ApiController]
[ApiController]
public class CustomersController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(Customer customer) { ... }
}
```

### Good (no diagnostic)

```csharp
// Bind a DTO, then set the tenant from a trusted source
[HttpPost]
public IActionResult Create([FromBody] CreateCustomerDto dto)
{
    var customer = new Customer
    {
        Name = dto.Name,
        TenantId = User.FindFirst("tenant_id")!.Value
    };
    db.Customers.Add(customer);
    db.SaveChanges();
    return Ok();
}
```

```csharp
// Non-tenant-scoped type — no diagnostic
[HttpPost]
public IActionResult Create([FromBody] CreateCustomerDto dto) { ... }
```

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL010.severity = none
```

Or mark the method with `[CrossTenant("reason")]`:

```csharp
[CrossTenant("Admin import — tenant set from authenticated context after binding")]
[HttpPost]
public IActionResult Import([FromBody] Customer customer) { ... }
```

## False-positive notes

- **Non-tenant-scoped types** (DTOs, view models) are not flagged.
- **`[FromServices]`**, **`[FromRoute]`**, **`[FromQuery]`**, **`[FromHeader]`** binding sources are not flagged.
- **Non-`[ApiController]` classes** without explicit `[FromBody]`/`[FromForm]` are not flagged (no implicit body binding).
- **Global entities** (configured via `tenantlint.global_entities`) are excluded.
- If the tenant property is set server-side after binding (e.g., in a filter or middleware), TL010 still fires. Mark the method `[CrossTenant]` or use a DTO to avoid the warning.
