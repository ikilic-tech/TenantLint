# TL015: Finbuckle TenantMismatchMode.Ignore allows cross-tenant writes

## What it detects

Assignment of `TenantMismatchMode.Ignore` to the `TenantMismatchMode` property on a Finbuckle `IMultiTenantDbContext`.

## Why it matters

`TenantMismatchMode.Ignore` allows saving an entity whose `TenantId` does not match the current tenant context. This enables silent cross-tenant writes — an entity belonging to tenant A can be saved through a context operating as tenant B.

The default `TenantMismatchMode.Throw` prevents this by throwing an exception.

## Examples

### Bad

```csharp
public class AppDbContext : MultiTenantDbContext
{
    public AppDbContext(ITenantInfo tenantInfo) : base(tenantInfo)
    {
        TenantMismatchMode = TenantMismatchMode.Ignore;
    }
}
```

### Good

```csharp
public class AppDbContext : MultiTenantDbContext
{
    public AppDbContext(ITenantInfo tenantInfo) : base(tenantInfo)
    {
        // TenantMismatchMode.Throw is the default — no need to set it
    }
}
```

## How to suppress

Mark the method or class with `[CrossTenant("reason")]`.

## False-positive notes

`TenantMismatchMode.Throw` and `TenantMismatchMode.Overwrite` are not flagged.
