# TL011: Pooled DbContext has tenant filter on constructor-only field

| Property   | Value              |
|------------|---------------------|
| ID         | TL011               |
| Category   | TenantIsolation     |
| Severity   | Warning             |
| Enabled    | Yes                 |
| Code Fix   | No                  |

## What it detects

TL011 fires at the `AddDbContextPool` or `AddPooledDbContextFactory` registration site when the registered DbContext type has a tenant query filter whose value is rooted in a field that is only assigned in the constructor — either because it is `readonly` or because no method/property outside the constructor writes to it.

A related diagnostic, **TL111** (Info, **disabled by default**), fires on the DbContext type itself — regardless of how it is registered — as a heads-up that the pattern is unsafe if pooling is ever introduced. To enable TL111, add the following to your `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.TL111.severity = suggestion
```

## Why it leaks

When a DbContext is pooled, the constructor runs **once per pool slot**. On subsequent uses, the runtime retrieves the instance from the pool **without re-invoking the constructor**. A field set only in the constructor retains the first tenant's value for every subsequent request that reuses that pool slot.

EF Core parameterizes query filter expressions through `this`, so the filter re-evaluates the field on each query. But if the field's value is stale (frozen at construction time), the "re-evaluated" value is still the wrong tenant's.

```csharp
// This LEAKS when pooled: _tenantId keeps the first tenant's value
public class AppDbContext : DbContext
{
    private readonly string _tenantId;

    public AppDbContext(DbContextOptions<AppDbContext> options, string tenantId) : base(options)
    {
        _tenantId = tenantId; // Only runs once per pool slot!
    }

    protected override void OnModelCreating(ModelBuilder m)
    {
        m.Entity<Order>().HasQueryFilter(e => e.TenantId == _tenantId);
    }
}

// Registration site — TL011 fires here:
services.AddDbContextPool<AppDbContext>((sp, o) => { ... });
```

## Examples

### Bad

```csharp
// TL011 at registration
public class AppDbContext : DbContext
{
    private readonly string _tenantId; // constructor-only field

    public AppDbContext(DbContextOptions<AppDbContext> o, string tenantId) : base(o)
    {
        _tenantId = tenantId;
    }

    protected override void OnModelCreating(ModelBuilder m)
    {
        m.Entity<Order>().HasQueryFilter(e => e.TenantId == _tenantId);
    }
}

// TL011: pooled + constructor-only tenant field
services.AddDbContextPool<AppDbContext>((sp, o) => o.UseSqlite("..."));
```

```csharp
// Also unsafe: service field injected via constructor and never reassigned
public class AppDbContext : DbContext
{
    private readonly ITenantService _tenantService;

    public AppDbContext(DbContextOptions<AppDbContext> o, ITenantService svc) : base(o)
    {
        _tenantService = svc;
    }

    protected override void OnModelCreating(ModelBuilder m)
    {
        m.Entity<Order>().HasQueryFilter(e => e.TenantId == _tenantService.TenantId);
    }
}
```

### Good

```csharp
// Mutable field — can be updated after pool retrieval
public class AppDbContext : DbContext
{
    private string _tenantId = null!;

    public void SetTenant(string tenantId) => _tenantId = tenantId;

    protected override void OnModelCreating(ModelBuilder m)
    {
        m.Entity<Order>().HasQueryFilter(e => e.TenantId == _tenantId);
    }
}

// Safe: set tenant after pool retrieval via IDbContextFactory pattern
services.AddPooledDbContextFactory<AppDbContext>(o => o.UseSqlite("..."));
```

```csharp
// Non-pooled registration — constructor-only fields are fine
services.AddDbContext<AppDbContext>((sp, o) => o.UseSqlite("..."));
```

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL011.severity = none
```

To enable the companion info diagnostic on the DbContext type itself:

```ini
[*.cs]
dotnet_diagnostic.TL111.severity = suggestion
```

## False-positive notes

- **Non-pooled registration** (`AddDbContext`) does not trigger TL011. Constructor-only fields are safe when the constructor runs per-request.
- **Fields with a setter or a method that writes to them** outside the constructor are not flagged — they can be updated after pool retrieval.
- **Readonly auto-properties** (e.g., `private string TenantId { get; }`) are not flagged in v0.2 — only explicit fields. This is a known limitation.
- **`IEntityTypeConfiguration`** classes are not analyzed for TL011/TL111.
