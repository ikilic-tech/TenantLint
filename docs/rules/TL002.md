# TL002: Raw SQL references tenant table without tenant filtering

| Property   | Value              |
|------------|--------------------|
| ID         | TL002              |
| Category   | TenantIsolation    |
| Severity   | Warning (Info when tenant column appears in predicate) |
| Enabled    | Yes                |
| Code Fix   | No                 |

## What it detects

TL002 fires when a raw SQL method (`ExecuteSqlRaw`, `ExecuteSql`, `ExecuteSqlInterpolated`, `SqlQueryRaw`, `SqlQuery`, and their `Async` variants) on `RelationalDatabaseFacadeExtensions` contains a constant or interpolated SQL string that references a known tenant table name.

## Why it leaks

Raw SQL bypasses EF Core's global query filters. When a raw SQL statement references a tenant-scoped table without filtering by the tenant column, it can read or modify data across all tenants.

```csharp
// This deletes rows from ALL tenants, not just the current one:
db.Database.ExecuteSqlRaw("DELETE FROM Customers WHERE IsDeleted = 1");
```

## Severity logic

- **Warning** (default): The SQL references a tenant table but no tenant column appears in a `WHERE`, `ON`, `AND`, or `OR` clause with a parameter placeholder.
- **Info**: A tenant column name (e.g., `tenant_id`, `TenantId`) appears in a predicate clause (`WHERE`, `ON`, `AND`, `OR`) adjacent to a parameter placeholder (`@param`, `{0}`, `$1`, `:param`). The filter is likely present but should be verified.

Tenant column in a `SELECT` list, `ORDER BY`, or `GROUP BY` does **not** downgrade to Info.

## Examples

### Bad (Warning)

```csharp
// TL002: 'ExecuteSqlRaw' references tenant table 'Customers' in raw SQL
// without apparent tenant filtering.
db.Database.ExecuteSqlRaw("DELETE FROM Customers WHERE IsDeleted = 1");
```

```csharp
// Tenant column in SELECT does not count as filtering:
db.Database.ExecuteSqlRaw("SELECT tenant_id, Name FROM Customers");
```

### Informational (Info)

```csharp
// Tenant column in WHERE with parameter — downgraded to Info:
db.Database.ExecuteSqlRaw(
    "DELETE FROM Customers WHERE tenant_id = @tid AND IsDeleted = 1", tenantId);
```

### Good (no diagnostic)

```csharp
// Non-tenant table — no diagnostic:
db.Database.ExecuteSqlRaw("DELETE FROM Countries WHERE Id = 1");
```

```csharp
// Non-constant SQL — no diagnostic (cannot analyze):
db.Database.ExecuteSqlRaw(GetDynamicSql());
```

```csharp
// Marked as intentional cross-tenant access:
[CrossTenant("Admin cleanup applies to all tenants")]
public void CleanupDeletedRecords(AppDbContext db)
{
    db.Database.ExecuteSqlRaw("DELETE FROM Customers WHERE IsDeleted = 1");
}
```

## Note on `FromSql*`

`FromSqlRaw` and `FromSqlInterpolated` are called on `DbSet<T>`, and EF Core composes global query filters over the raw SQL (wrapping it as a subquery). Therefore, `FromSql*` queries on a tenant-scoped entity are protected by the tenant filter and are **not** flagged by TL002.

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL002.severity = none
```

Or mark the method with `[CrossTenant("reason")]`:

```csharp
[CrossTenant("Billing reconciliation requires cross-tenant data")]
public void Reconcile() { ... }
```

## False-positive notes

- **Non-constant SQL** is not analyzed. If the SQL is built at runtime (e.g., `GetSql()`, string concatenation with non-constant values), TL002 does not report.
- **Non-tenant tables** are not flagged. Only tables associated with tenant-scoped entities (discovered via `HasQueryFilter` or convention) are checked.
- **Global entities** (configured via `tenantlint.global_entities`) are excluded.
- **User-defined methods** named `ExecuteSqlRaw` etc. on types other than `RelationalDatabaseFacadeExtensions` are not flagged.
- **Word boundaries** are checked. A table named `Customers` will not match SQL containing `CustomerLogs`.
- **Heuristic limitation**: The predicate detection uses simple keyword scanning, not full SQL parsing. Complex subqueries or CTEs may not be correctly classified.
