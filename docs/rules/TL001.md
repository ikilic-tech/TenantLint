# TL001: IgnoreQueryFilters() removes tenant filter

| Property   | Value              |
|------------|--------------------|
| ID         | TL001              |
| Category   | TenantIsolation    |
| Severity   | Warning            |
| Enabled    | Yes                |
| Code Fix   | Yes                |

## What it detects

TL001 fires when `IgnoreQueryFilters()` is called **without arguments** on an `IQueryable<T>` where `T` is a tenant-scoped entity (including chains ending with `ExecuteUpdate` or `ExecuteDelete`). The parameterless overload removes **all** query filters, including the tenant isolation filter.

## Why it leaks

EF Core global query filters are the primary mechanism for enforcing tenant isolation at the data layer. Calling `IgnoreQueryFilters()` without arguments strips every filter, including the one that restricts rows to the current tenant. The resulting query returns data from **all tenants**.

```csharp
// This returns customers from ALL tenants, not just the current one:
var all = db.Customers.IgnoreQueryFilters().ToList();
```

## Examples

### Bad

```csharp
// TL001: 'Customer' query removes the tenant filter via IgnoreQueryFilters().
var results = db.Customers.IgnoreQueryFilters().Where(c => !c.IsDeleted).ToList();
```

```csharp
// TL001 also catches ExecuteUpdate/ExecuteDelete chains:
db.Orders.IgnoreQueryFilters().ExecuteDelete();
```

### Good (EF Core 10+ with named filters)

```csharp
// Only remove the soft-delete filter; the tenant filter stays in place:
var results = db.Customers.IgnoreQueryFilters(["SoftDelete"]).Where(c => c.IsArchived).ToList();
```

### Good (any EF Core version)

```csharp
[CrossTenant("Admin dashboard aggregates data across all tenants")]
public List<Customer> GetAllCustomers()
{
    return _context.Customers.IgnoreQueryFilters().ToList();
}
```

## Code fix

TL001 offers up to two code fixes depending on the project:

### Fix A: Use selective `IgnoreQueryFilters(["..."])`

**Available when:** EF Core 10+ and at least one non-tenant named filter exists on the entity.

Rewrites `.IgnoreQueryFilters()` to `.IgnoreQueryFilters(["SoftDelete", "Archive"])`, listing only the non-tenant named filters. The tenant filter remains active.

### Fix B: Add `[CrossTenant("")]`

**Available when:** A `CrossTenantAttribute` class exists in the compilation.

Adds `[CrossTenant("")]` to the enclosing method. TL901 will then flag the empty reason string, prompting the developer to document why cross-tenant access is intentional.

## How to suppress

```ini
[*.cs]
dotnet_diagnostic.TL001.severity = none
```

Or mark the method with `[CrossTenant("reason")]`:

```csharp
[CrossTenant("Billing reconciliation requires cross-tenant order comparison")]
public decimal ReconcileBilling() { ... }
```

## False-positive notes

- **Non-tenant entities** are not flagged. If the entity type has no tenant property (by convention or explicit configuration), `IgnoreQueryFilters()` on it does not trigger TL001.
- **Global entities** (configured via `tenantlint.global_entities` in `.editorconfig`) are excluded.
- **User-defined methods** named `IgnoreQueryFilters` are not flagged. TL001 only detects calls to `Microsoft.EntityFrameworkCore.EntityFrameworkQueryableExtensions.IgnoreQueryFilters`.
- **Selective `IgnoreQueryFilters(["..."])`** (EF Core 10+) is not flagged, as it preserves the tenant filter.

## Related pitfall: Find/FindAsync bypasses query filters for tracked entities

`DbSet.Find` and `FindAsync` check the change tracker before querying the database.
If a cross-tenant entity is already tracked (e.g., loaded via `IgnoreQueryFilters()`
or raw SQL), `Find` returns it **without applying the query filter**.

Regular LINQ queries (`Where`, `ToList`, etc.) are not affected — query filters apply
to the database query regardless of tracked entities.

This behavior is by design in EF Core and applies to both EF Core 8 and 10.
